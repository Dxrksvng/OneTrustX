## Q&A ที่น่าจะเจอ

**ต่างจาก BRS อย่างไร** BRS ตอบว่ากระเป๋าใบนี้อยู่ที่ไหน และมีแจ้งเตือนบางประเภท (no-show, ลงผิดตู้) เราไม่ติดตามรายใบ เราดูการไหลรายขั้นเทียบเวลาออกของเที่ยวบิน ไม่ควรพูดว่า BRS ทำไม่ได้

**ตัวเลขมาจากไหน** จากแบบจำลองที่เราสร้างและรัน 30 รอบต่อสถานการณ์ ข้อมูลเป็นข้อมูลสังเคราะห์ ค่าตั้งต้นทุกค่ามีป้ายว่าเป็นข้อมูลจริง อ้างอิง หรือสมมติฐาน ผลทั้งหมดไม่ใช่ผลของสนามบินจริง

**ถ้า handler จริงจัดลำดับดีอยู่แล้ว ประโยชน์เหลือเท่าไร** น้อยกว่าตัวเลขบนสไลด์ เพราะวิธีเดิมที่ใช้เทียบเป็นสมมติฐาน (แบ่งกำลังเท่ากัน) จึงต้องถามผู้เชี่ยวชาญก่อนรอบ prototype ประโยชน์ที่ไม่ขึ้นกับสมมติฐานนี้คือการเห็นคอขวดและเตือนล่วงหน้า

**คนมาไม่ได้ ระบบแก้อะไร** ไม่แก้ปัญหาคนมาไม่ได้ ช่วยให้ใช้คนที่เหลือกับเที่ยวบินที่ปิดก่อน และบอกให้รู้เร็วว่าเมื่อใดเร่งงานไม่พอและต้องลดภาระ (ในเหตุการณ์จริงการงดรับ cargo และลดเที่ยวบินเกิดวันที่ห้า)

**ทำไมสไลด์รอบแรกมีเลข 86% / 100% / 50% แต่รอบนี้เปลี่ยน** รอบแรกเป็นค่าประมาณเบื้องต้นจากชุดจำลองเที่ยวบินเดียว รอบนี้วัดจากแบบจำลองกระเป๋าที่ละเอียดขึ้น ค่าหลักอยู่ระดับเดียวกัน (F1 87%, กระเป๋าตกเที่ยวบินลด 53.5%) แต่ป้ายตัวชี้วัดต้องตรงกับสิ่งที่วัดจริง

**ทำไมไม่ใช้ blockchain** สิ่งที่ต้องการคือบันทึกเหตุการณ์ที่ตรวจย้อนได้ ว่าใครแจ้ง เมื่อไร และใครตัดสินใจอะไร ต้นแบบทำด้วยบันทึกที่มีที่มาและ checksum ระบบจริงเลือก permissioned ledger หรือ event store ที่ป้องกันการแก้ไขได้ตามนโยบายสนามบิน

**ใช้ AI หรือ LLM ไหม** ต้นแบบใช้กฎที่ตรวจย้อนได้ ไม่ใช้ LLM และไม่ใช้ machine learning ในการตัดสินใจ ML เป็นตัวเลือกในอนาคต แต่ต้องชนะวิธีพื้นฐานบนข้อมูลจริงก่อน

**PDPA** ใช้เฉพาะจำนวนรวมรายเที่ยวบินและรายขั้น ไม่ใช้ชื่อผู้โดยสาร เลขหนังสือเดินทาง หรือเลขป้ายกระเป๋า ก่อนรับข้อมูลจริงต้องมีข้อตกลงการใช้ข้อมูลและทบทวนตาม PDPA

**ใครจ่ายเงิน และคุ้มไหม** ยังไม่มีแบบจำลองธุรกิจ ในแบบจำลองน้ำท่วม กระเป๋าที่ไม่ตกเที่ยวบินเฉลี่ย 161.8 ใบต่อกะ คิดตามต้นทุนเฉลี่ย 260 ดอลลาร์ต่อใบของ SITA เท่ากับประมาณ 42,000 ดอลลาร์ต่อกะที่เกิดเหตุ นี่เป็นค่าประมาณจากแบบจำลอง ไม่ควรขยายเป็นตัวเลขระดับประเทศ
