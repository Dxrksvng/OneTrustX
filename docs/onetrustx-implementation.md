# One TrustX implementation

One TrustX is the collaborative event and decision layer in this repository. It keeps the Airport TimeTwin forecast/simulation modules and adds stakeholder events, verification metadata, conflict reconciliation, a Common Operational State, human decisions, audit history, and an experiment/KPI layer.

## Run

```bash
cp .env.example .env
docker compose --env-file .env -f infra/docker-compose.yml up -d --build
```

Open `/trustx` for the overview. The guided product demo remains at `/demo`; the original TimeTwin routes remain available. The local API is documented at `/docs`.

## Evidence boundary

The S1–S8 scenario pack is a deterministic **SIMULATED MVP RESULT — Not actual airport performance**. BKK identity and public context remain sourced through the existing provenance pipeline; checkpoint configuration, stakeholder events, and outcomes are modelled assumptions. The trust layer records source identity, lineage, ordering and rule results. Verification does not prove physical-world truth.

Run the reproducible 100-seed-per-condition evidence pack:

```bash
python3 scripts/experiments/run_trustx_experiment.py
```

It writes `data/cache/onetrustx-experiment.json` with the same episode under BASELINE, SHARED_DATA, TRUST_NO_AI, ONE_TRUSTX, and ONE_TRUSTX_AI, plus P25/median/P75 summaries and sensitivity/ablation metadata. The result is suitable for prototype validation and must not be presented as an airport deployment KPI.

## Main API

All new endpoints are namespaced under `/api/trustx`: scenarios, events, shared state, conflicts, predictions, recommendations, decisions, experiments, and KPI definitions/results. The seed uses stable IDs and startup idempotency so refreshes do not duplicate decisions or audit evidence.

## Source lineage

OpenSky, OurAirports and Open-Meteo are external open-data context adapters where cached data is available. Detailed operational event streams are generated by `process-generator-1.0` under `trust-rules-1.0`. See `/trustx/sources`, `docs/data-quality-report.md`, and `docs/assumptions.md` for the boundary and limitations.
